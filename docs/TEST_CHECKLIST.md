# รายการตรวจเมื่อมีฮาร์ดแวร์

ยังไม่ได้ทดสอบรายการต่อไปนี้บน ESP32 จริง ช่องว่างหมายถึงรอทดสอบ ไม่ใช่ผ่านแล้ว

## ตรวจบอร์ดผ่าน USB

- [ ] ยืนยันชื่อบอร์ด/ชิปจริง และเปลี่ยน `board = esp32dev` ถ้าจำเป็น
- [ ] ถอดวงจรโหลดออก เหลือ ESP32 กับสาย USB ที่รับส่งข้อมูลได้
- [ ] ตรวจพอร์ตด้วย `pio device list` ไม่เลือก COM1 เพียงเพราะเป็นพอร์ตเดียวที่พบ
- [ ] อัปโหลด `esp32-check`: `pio run -e esp32-check -t upload --upload-port COMx` โดยแทน COMx ด้วยพอร์ตจริง
- [ ] เปิด `pio device monitor --port COMx --baud 115200` แล้วเห็นชื่อชิปและ heartbeat ทุก 2 วินาที
- [ ] ปิด Serial Monitor ก่อนอัปโหลดครั้งถัดไปถ้าพอร์ตถูกใช้งานอยู่

## Serial demo

- [ ] ยืนยัน `kRelayOutputEnabled = false`
- [ ] อัปโหลด `blynk-mqtt` โดยยังไม่ต้องมี `secrets.h`
- [ ] หลังบูตเห็น `SIMULATION`, `Relay=OFF` และข้อความ credentials missing
- [ ] ส่ง `on` และ Enter แล้วเห็น `Relay=ON`
- [ ] ส่ง `off` แล้วเห็น `Relay=OFF`
- [ ] ส่ง `status`/`help` แล้วเห็นข้อมูลถูกต้อง
- [ ] รีเซตบอร์ดแล้วกลับ OFF

## Blynk ผ่าน MQTT ในโหมดจำลอง

- [ ] สร้าง V0/V1 โดยชื่อ `Relay Command` และ `Commanded Output` ตรงกับ `MQTT_SETUP.md` และกรอก `secrets.h`
- [ ] Build `blynk-mqtt` และอัปโหลดใหม่ แล้วเห็น MQTT connected และ Device Online ใน Blynk
- [ ] ถ้ามี redirect ให้ตรวจว่าเปลี่ยนไป region ของ Blynk และเชื่อมต่อสำเร็จ
- [ ] กด V0 ON/OFF และตรวจ Serial กับ V1 ให้ตรงกัน
- [ ] ตอน ON ให้ตัด Wi-Fi ทดสอบ: เมื่อโปรแกรมตรวจพบการหลุดต้องเปลี่ยน OFF
- [ ] ต่อ Wi-Fi กลับ: เชื่อม Blynk รอบใหม่แล้ว V0/V1 เป็น OFF ไม่เปิดเองจากคำสั่งเก่า
- [ ] ทดสอบ Cloud ขาดขณะที่ Wi-Fi ยังต่อ: ตรวจว่าเมื่อไลบรารีตรวจพบ จะเปลี่ยน OFF
- [ ] รีเซต/ต่อ MQTT ใหม่เมื่อแอปเคยค้าง ON: ต้องเริ่ม OFF และ V0/V1 เป็น 0
- [ ] ใช้ Serial `on/off` ในโหมดจำลองตอน MQTT ต่ออยู่: V0/V1 ต้องเปลี่ยนตามโดยไม่มีวงจรส่งข้อความวน
- [ ] ทดสอบกรณี Token ผิดหรือ NTP ใช้ไม่ได้: ต้องไม่เปิด hardware output
- [ ] ไม่เปิด MQTT client อื่นด้วย Device Token เดียวกันระหว่างทดสอบ

## รีเลย์ DC ในอนาคต

- [ ] ยืนยันโมดูล แรงดันจ่าย ลอจิก 3.3V ขา GPIO และ Active LOW/HIGH
- [ ] ตรวจวงจรให้เริ่ม OFF ระหว่างบูต/รีเซตด้วยฮาร์ดแวร์
- [ ] ใช้โหลด DC แรงดันต่ำก่อน แล้วจึงเปิด `kRelayOutputEnabled` และ build ใหม่
- [ ] ตรวจว่าคำสั่งในแอปกับหน้าสัมผัสจริงตรงกัน และทดสอบรีเซต/การเชื่อมต่อหลุด

โปรเจกต์นี้ยังไม่มีการวัดกระแส กำลังไฟ หรือพลังงาน และสถานะ V1 ไม่ได้ยืนยันว่าเต้ารับไม่มีไฟ
